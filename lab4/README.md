## Описание

Бэкенд-сервер на **Express.js** с полноценным REST API для коллекции карточек (`stocks`). Карточки описывают этапы траектории полёта к Луне. Данные хранятся в JSON-файле на диске — без базы данных.

Основная цель лабораторной работы — освоить архитектуру Express-приложения: маршруты, контроллеры, сервисы, middleware, обработку ошибок и тестирование API через Postman.

---

## Стек технологий

- **Node.js** — среда выполнения
- **Express 5** — веб-фреймворк
- **Nodemon** — горячая перезагрузка при разработке
- **fs (встроенный модуль)** — чтение и запись JSON-файла

## Архитектура приложения

Приложение разделено на слои по принципу **Controller → Service → FileService → данные**:

```
example-express/
└── src/
    ├── index.js                  # Точка входа: Express app, middleware, запуск
    ├── routes/
    │   └── stocks.js             # Маршруты /stocks
    ├── controllers/
    │   └── stocksController.js   # Обработчики запросов
    ├── services/
    │   ├── stocksService.js      # Бизнес-логика (CRUD)
    │   └── fileService.js        # Чтение / запись JSON-файла
    └── data/
        └── stocks.json           # Хранилище данных
```

### Поток запроса

```
HTTP-запрос
  → Router (routes/stocks.js)
  → Controller (stocksController.js)   — разбирает параметры, формирует ответ
  → Service (stocksService.js)         — бизнес-логика: поиск, создание, обновление
  → FileService (fileService.js)       — readFileSync / writeFileSync
  → stocks.json
```

### stocksService

Инициализируется один раз при старте сервера (`stocksService.init(filePath)`), после чего знает путь к файлу данных. Предоставляет методы:

| Метод | Что делает |
|-------|-----------|
| `findAll(title?)` | Вернуть все карточки; если передан `title` — фильтрация по подстроке |
| `findOne(id)` | Найти карточку по `id` |
| `create(data)` | Создать новую карточку с авто-генерируемым `id` |
| `update(id, data)` | Частичное обновление (`PATCH`) — мержит поля |
| `replace(id, data)` | Полная замена (`PUT`) — перезаписывает все поля |
| `remove(id)` | Удалить карточку |

## Middleware

В `index.js` подключены три middleware в цепочке:

| # | Middleware | Что делает |
|---|-----------|-----------|
| 1 | `express.json()` | Парсит тело запроса как JSON |
| 2 | Логирующий | Выводит в консоль метод и URL каждого запроса |
| 3 | 404-обработчик | Возвращает `{ error: 'Маршрут не найден' }` для неизвестных путей |

Плюс глобальный обработчик ошибок (4 аргумента — `err, req, res, next`) — возвращает 500.

## API бэкенда

Базовый URL: `http://localhost:3000`

### Коллекция `/stocks`

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/stocks` | Получить все карточки |
| `GET` | `/stocks?title=орбита` | Фильтрация по названию (поиск подстроки, регистронезависимо) |
| `POST` | `/stocks` | Создать карточку |
| `OPTIONS` | `/stocks` | Допустимые методы (`Allow: GET, POST, OPTIONS`) |

### Отдельный ресурс `/stocks/:id`

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/stocks/:id` | Получить карточку по ID |
| `PATCH` | `/stocks/:id` | Частичное обновление (любое подмножество полей) |
| `PUT` | `/stocks/:id` | Полная замена (нужны все поля: `src`, `title`, `text`) |
| `DELETE` | `/stocks/:id` | Удалить карточку |
| `HEAD` | `/stocks/:id` | Проверить существование (без тела, заголовок `Content-Length`) |
| `OPTIONS` | `/stocks/:id` | Допустимые методы (`Allow: GET, PUT, PATCH, DELETE, HEAD, OPTIONS`) |

### Тело запроса (POST / PUT / PATCH)

```json
{
  "src": "https://images.unsplash.com/...",
  "title": "Название этапа",
  "text": "Описание этапа"
}
```

- `POST` и `PUT` — требуют все три поля, иначе `400 Bad Request`
- `PATCH` — принимает любое подмножество полей

### Коды ответов

| Код | Ситуация |
|-----|---------|
| `200` | Успешный GET / PATCH / PUT |
| `201` | Карточка успешно создана (POST) |
| `204` | Карточка удалена (DELETE, тело пустое) |
| `400` | Не все обязательные поля переданы |
| `404` | Карточка не найдена / маршрут не существует |
| `500` | Внутренняя ошибка сервера |

## Запуск проекта

```bash
cd example-express
npm install
npm run dev      # с горячей перезагрузкой (nodemon)
# или
npm start        # запуск без перезагрузки
```

Сервер запустится по адресу `http://localhost:3000`. В терминале появится:

```
Сервер запущен по адресу http://localhost:3000
```
